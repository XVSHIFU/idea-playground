Linux 服务管理指南

从 systemd 基础到生产环境的守护进程实践——一篇写给 SRE 与后端工程师的实用笔记。

引言

在 Linux 系统中，服务（service）是长期运行在后台、等待请求或执行周期性任务的进程。从 Web 服务器到日志收集器，从定时备份到监控代理，几乎所有生产级组件都以「服务」的形式存在。

理解如何正确地定义、启动、监控和排障一个服务，是系统管理员和 SRE 的核心技能之一。本文以 systemd 为主线，梳理一条从概念到实践、从编写 unit 到定位故障的完整路径。

systemd 的核心模型

systemd 是现代 Linux 发行版的初始化系统和服务管理器。它以 unit 为基本单位描述系统中的各类资源，其中最常见的三种是：

  • .service —— 描述一个可执行的服务进程
  • .socket —— 描述一个监听端口的套接字
  • .timer —— 描述一个定时触发器
与 SysVinit 的 shell 脚本不同，systemd 使用声明式的 unit 文件，并通过 cgroup 精确追踪进程树，这使得服务依赖、重启策略和资源限制都变得可描述。

服务的生命周期

一个服务从被触发到最终退出，大致经历以下状态流转：

inactive → activating → active → deactivating → inactive

使用 systemctl 可以观察和控制这一过程：

bash 
# 查看服务当前状态
sudo systemctl status nginx.service

# 启动、停止、重启
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx

# 设置开机自启
sudo systemctl enable nginx

提示：自定义的 unit 文件应放在 /etc/systemd/system/，系统自带的通常位于 /usr/lib/systemd/system/。后者在包升级时可能被覆盖，不建议直接修改。

编写一个 unit 文件

一个最小可用的 service 单元通常包含三部分：[Unit]、[Service] 和 [Install]。

ini 
[Unit]
Description=My Background Worker
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/worker --config /etc/worker.conf
Restart=on-failure
RestartSec=5
User=worker
Group=worker
WorkingDirectory=/var/lib/worker

[Install]
WantedBy=multi-user.target

把文件放到 /etc/systemd/system/worker.service，然后执行 sudo systemctl daemon-reload 使其生效。

常用 unit 类型速查

Unit 类型用途典型文件
.service长期运行的服务进程nginx.service
.socket监听套接字，按需激活服务sshd.socket
.timer基于时间的定时触发器logrotate.timer
.target一组 unit 的逻辑分组multi-user.target

排查常见问题

服务启动失败，如何定位原因？

先看 systemctl status 输出末尾的日志，再用 journalctl -u <service> -n 50 --no-pager 查看最近 50 行日志。检查 unit 文件路径、文件权限，以及 ExecStart 指向的可执行文件是否存在。

修改 unit 文件后为什么没有生效？

systemd 会缓存 unit 文件的解析结果，修改后必须执行 systemctl daemon-reload。如果修改的是 [Service] 段，还需要 systemctl restart <service> 重新拉起进程。

如何查看某个服务的全部日志？

使用 journalctl -u <service> 查看全部日志，加 -f 实时跟踪，加 --since "1 hour ago" 限定时间范围。若日志已被清理，可查看 /var/log/ 下服务自身写入的文件。

最佳实践

把服务写好只是第一步，让它能在生产环境中稳定、安全、可观测地运行，才是工程上的关键。

注意：生产环境的服务应始终设置 Restart=on-failure 与合理的 RestartSec，并通过 User= 以非 root 身份运行。避免在 ExecStart 中使用 shell 管道，优先编写独立脚本。

此外，建议为每个服务配置资源限制（MemoryMax、CPUQuota）与日志速率限制（LogRateLimitIntervalSec），并在 [Unit] 中显式声明依赖关系，减少启动顺序带来的不确定性。

雨天的城市

有些夜晚，不需要发生什么。

雨是从傍晚开始下的。

起初只是零星几点，落在窗玻璃上，汇成一条条细线，再慢慢地滑下去，把窗外的霓虹拉成模糊的光带。我没有开灯，就坐在窗边，看城市被一点点洗旧。

移动的蘑菇

街上的行人撑起了伞。红的、黑的、格子的，像一朵朵移动的蘑菇。有个女孩没带伞，抱着书包在屋檐下小跑，鞋跟踩在水洼里，溅起一小朵水花。她停下来，仰头看了看天，然后笑了——那种「算了吧」的笑。

雨天的城市有一种奇怪的温柔。

被雨水吸走的声音

车流的声音被雨水吸走了一半，剩下的一半变得钝钝的，像隔着一层棉。便利店的门开了又关，暖黄的光漏出来，把门口的雨帘照亮了一小片。

我想起小时候，夏天的暴雨。那时候没有伞，就顶着书包跑回家，浑身湿透，被母亲骂一顿，然后喝一碗姜茶。那碗姜茶的味道，到现在还记得。

雨还在下

城市的灯一盏盏亮起来，一盏盏又暗下去。我起身开了灯，泡了杯茶，坐回窗边。

有些夜晚，不需要发生什么。
