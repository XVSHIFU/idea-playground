# 味道的音符

一份可以听的味觉记谱。

把一次烹饪的每一步算成"随时间变化的味道强度"，再把这份记谱奏成声音。
听到的是**过程**，尝到的是整段累积下来、留在舌头上的那一份。揭晓之前你可以先猜。

## 怎么玩

打开 <http://127.0.0.1:4301/>（或从游乐场入口进入）。

1. **听一听这道菜**：按谱播放一遍，同时看到曲线被逐段描出来。点谱面任意位置可以听那一瞬间最重的那种味道；点右侧某一步可以从那里开始听。
2. **猜一下**：在揭晓之前选一个你猜的味道。它只是给你自己留个记录，不影响结果。
3. **揭晓尝到的味道**：曲线被填满，出现"留在舌头上的这一份"横条，并给出听觉高点与味觉高点的位置对照。
4. **换一种做法**：爆炒 / 慢炖 / 白灼 / 清蒸 会重算整份记谱——时间尺度、曲率、留存全部跟着变。同一道菜因此有两段完全不同的音乐。
5. **换一道菜**：六道菜，从蒜蓉炒青菜到麻婆豆腐；其中"麻"是故意留着的空位。

键盘：空格播放／停止，← → 在谱面上移动光标。速度滑块 0.5×–2×。

## 机制

- `recipes.js` 是六道菜的记谱数据。每一步写清：什么时候开始（按分钟）、持续多久、手在做什么，以及这一步里八种味道的强度。
  真实发生的感官现象写在每步的 `note` 里（例如"焦化的苦会晚一些才被尝到"）；强度数值是为这个作品选的记谱参数，不是实测数据。
- `engine.js` 把菜 × 做法算成曲线。做法改写时间尺度与曲率；八种味道各有自己的涨落形状：咸是一碰就走，酸是刺一下就收，油脂起音慢尾巴长，
  焦化的第二层比第一层晚出现，稠化把噪声抹圆，"麻"是持续的高频搏动。留存是整段累积量的加权（对最重的那一下更敏感），代表舌头拿到的部分。
- `audio.js` 把曲线奏成声音。每种味道对应一种声音行为，不是配一段音效。界面看到的和听到的是同一份数据。
- 侧栏的"听觉高点"（平均亮度最高的一瞬）与"味觉高点"（留存最重的位置）之差，就是这件作品想让人看见的那个错位。

## 边界与说明

- 纯静态：不需要后端、端口（本机入口除外）、网络或构建步骤，全部资源用相对路径。
- 音频由 Web Audio 实时合成，没有音频文件；需要一次点击才会出声（浏览器策略）。
- 存档只有一个键 `taste-score:state:v1`，记录上次的菜、做法、速度与是否已揭晓。
- 曲线是记谱，不是这段烹饪的实录，也不是食品科学结论。
- 检查：`node --test taste-score/tests/` 验证的是作品的规矩——换做法是否真的改写记谱、听觉与味觉落点是否真的错开。
  不能创建子进程时可以跑 `node taste-score/tests/run.mjs`；`node taste-score/tests/selfcheck.mjs` 用 DOM 桩把 `app.js` 的初始化与交互回调真跑一遍。
