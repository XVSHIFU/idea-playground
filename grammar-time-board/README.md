# 昨天今天明天

一个用句子改变世界的 2–4 人桌游，提供可直接玩的 HTML 版与纸笔版。你可以让一句话立刻成真、把它写成不易改变的过去，或押在自己的下个回合。第一版的目标是检验：同一个动作换一种说法，是否真的让玩家作出不同选择。

当前规则为 v0.1，建议预留 20 分钟；时长与平衡性尚未经过真人试玩。

## 在浏览器里玩

双击 [index.html](index.html)，即可在浏览器中打开。保留同目录下的 `styles.css`、`engine.js`、`app.js`。不需要安装依赖、启动服务或连接网络。

- 默认双人开局；“开新一局”可设置 2–4 人、名字、先手，以及可选的“以后都……”桌规实验。
- 轮到你时选句式与动作，把示例句读出来，也可以自由改写；同桌确认意思后点击“让这句话生效”。自由文本只记录说法，结算依据始终是选定的操作，不作自然语言理解。
- 三件物品显示现状；时间轨显示封签与待办。信用、失约、打断、条件、轮次和胜利均自动结算。
- 点击“交给下一位”才进入下个回合，方便同桌看清发生了什么。刷新可恢复当前浏览器内已确认的回合进度；尚未确认的草稿不保存。浏览器限制存储时，页脚会明确提示。
- “怎么玩”可展开规则；“这一局，我们说过的话”可回看完整操作记录。

核心文件：`index.html` 是界面，`styles.css` 是样式，`engine.js` 是不依赖页面的规则引擎，`app.js` 负责操作、呈现与本机存档。

开发验证：安装 Node.js 的环境可执行 `node --test tests/engine.test.cjs`。浏览器验证脚本 `tests/browser.cjs` 使用 Playwright 与本机 Edge；可用 `GRAMMAR_PLAYWRIGHT_MODULE` 指向已有 Playwright 模块。这些工具只用于开发验证，玩游戏不需要它们。

## 用纸笔玩

1. 阅读 [规则](RULES.md)。
2. 打印 [PDF 试玩包](output/pdf/昨天今天明天-纸笔试玩包.pdf)，A4 纵向，共 3 页：棋盘、裁切卡片、桌边规则。也可以在浏览器打开 [可编辑的打印源文件](print.html)，或照着手画。
3. 准备笔、剪刀和每人 3 枚硬币或豆子；每人先领取其中 2 枚作信用。
4. 用 [独立工作区文件](grammar-time-board.code-workspace) 打开本目录，后续材料都放在这里。

## 事实背景与游戏化虚构

**事实背景：**语言学中的时态与体貌不是同一个分类维度；进行表达可以与不同的时间指向组合，各语言的语法化方式也不相同。参见 Dahl 与 Velupillai 的 WALS [体貌章节](https://wals.info/chapter/65)和[过去时章节](https://wals.info/chapter/66)。条件关系讨论的是一个命题成立与另一个命题成立之间的关系，不能直接称为一种“假设时态”。参见 SIL 的[条件关系词条](https://glossary.sil.org/term/conditional-relation)。来源核对日期：2026-10-03。

**游戏化虚构：**“过去需要 2 信用”“正在做会被打断”“明天会做是一张承诺”“以后都能修改桌规”，全部是本游戏的设计，不是语言学事实。棋盘上的过去、现在、未来是操作区；“已经”在本游戏里被约定为过去模式的提示词，不据此给中文句子作正式语法分类。过去模式也不真的重演或倒转历史，只是当下写入一个带封签的结果。

原构想中的自由情态组合、反事实、递归条件与永久规则保留为研究方向。v0.1 先让几种句式有稳定、可结算的含义；“能、必须、想”暂不单独增加效果。

## 这一版的取舍

- 桥、门共用，钥匙只有一把。胜利要求钥匙在自己手里，避免同一共享状态让所有人同时获胜。
- 六种动作公开可选，补齐“开、关、拿”等必要操作；第一局不用随机抽卡阻断基本行动。
- 过去的保护会到期；进行、承诺、条件最多各等待到自己的下个回合，不积累无限队列。
- 同桌玩家只澄清意图，不以投票阻止合法行动；无法说清时可改述，最后有明确的结束争议办法。

## 试玩后只记三件事

- 哪一句话产生了“换种说法，结果真的不同”的感觉？
- 哪次结算需要翻规则或发生争执？记下原句与当时的状态。
- 哪种句式始终无人选择，或者所有人一直重复使用？

这是待验证的原型。示例推演只能说明规则如何结算，不能代替真实玩家对乐趣、先手优势和时长的反馈。
