03发行版

将内核、工具、软件包、配置和服务组合成可用系统。

04systemd

现代多数发行版的服务、启动和日志管理基础。

文件系统与目录结构

记住「一切从 / 开始」，再学会路径和文件操作。

Linux 采用统一的目录树。磁盘、分区、网络存储等通过挂载接入这棵树；盘符并不是核心概念。

目录典型用途管理提示
/etc系统与服务配置改动前先备份
/var日志、缓存、队列、动态数据容易产生容量问题
/home普通用户主目录关注权限和配额
/usr程序与共享资源不要随意修改受包管理器管理的文件
/tmp临时文件可能被自动清理
/dev设备节点磁盘名须核实
/proc、/sys内核与运行状态的虚拟接口并非普通持久文件
路径与目录操作BASH
pwd
ls -lah /etc
cd /var/log
cd ..
cd ~
mkdir -p ~/linux-lab/docs
cp /etc/hosts ~/linux-lab/docs/hosts.bak
mv ~/linux-lab/docs/hosts.bak ~/linux-lab/docs/hosts.copy
ls -l ~/linux-lab/docs

绝对路径与相对路径

/etc/hosts 从根目录定位；docs/hosts.copy 从当前工作目录定位；~ 指当前用户的主目录。

!
删除是高风险操作

rm 没有通用回收站。先用 ls 或 find 验证目标；交互删除用 rm -i。尤其不要执行来历不明的 rm -rf。

用户、用户组与权限

理解谁可以访问什么，比记住 chmod 更重要。

权限由 所有者（user）／所属组（group）／其他人（other） 三组构成，每组包含读 r、写 w、执行 x。

-rw-r-----普通文件 · 所有者读写 / 组只读 / 其他人无权限
6rw-
4r--
0---
账户与权限检查BASH
id
getent passwd root
getent group
ls -ld /home
ls -l /etc/passwd
sudo -l
创建用户和授权（实验机）BASH
sudo useradd -m -s /bin/bash alice
sudo passwd alice
sudo groupadd operators
sudo usermod -aG operators alice
id alice
sudo chown alice:operators /home/alice
sudo chmod 750 /home/alice

sudo 组有发行版差异

有条件地赋予 sudo 权限（仅授权管理员）BASH
# Ubuntu / Debian 常见
sudo usermod -aG sudo alice
# RHEL / Rocky / AlmaLinux 常见
sudo usermod -aG wheel alice
文件权限与 ACLBASH
chmod 640 report.txt
chmod u+x deploy.sh
chown alice:operators report.txt
getfacl report.txt
setfacl -m u:alice:r report.txt
!
不要把 777 当作「权限修复」

chmod 777 会让所有用户都能写入，是常见的安全错误。先判断属主、所属组、目录执行位和服务运行账户，再决定最小必要权限。

进程、服务与 systemd

从「命令能执行」到「服务能持续可靠运行」。

程序运行起来就是进程（PID）。系统服务通常由 systemd 管理，常见单位（unit）类型包括 .service、.timer 和 .mount。

观察进程与资源BASH
ps aux | head -n 15
pgrep -a sshd
top
kill -TERM 12345    # 仅在确认 PID 后执行；先尝试优雅结束
systemctl 服务生命周期BASH
systemctl list-units --type=service --state=running
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx
sudo systemctl reload nginx
sudo systemctl enable nginx
sudo systemctl disable nginx
systemctl status nginx --no-pager

服务启动失败怎么办？

服务诊断的黄金组合BASH
systemctl status nginx --no-pager -l
journalctl -u nginx -n 80 --no-pager
systemctl cat nginx
ss -lntp
# 修改 unit 文件后才需要：
sudo systemctl daemon-reload
✦
start 与 enable 是两回事

start 影响当前运行状态，enable 决定是否按预设依赖关系在启动时启用。enable --now 可以同时进行，但要确认这是你想要的行为。

磁盘、文件系统与挂载

诊断「空间不足」前，先弄清容量、分区与挂载点。

安全的只读检查BASH
lsblk -f
blkid
df -hT
du -sh /var/log
du -xhd1 /var 2>/dev/null | sort -h
findmnt
cat /etc/fstab

磁盘管理的四个对象

块设备→分区→文件系统→挂载点

lsblk 看块设备与挂载结构，df 看文件系统可用容量，du 看目录占用，findmnt 看挂载关系。两者结果不一致时，还应考虑已删除但仍被进程占用的文件。

通过 UUID 查看与验证挂载配置BASH
lsblk -o NAME,SIZE,FSTYPE,UUID,MOUNTPOINTS
findmnt --verify
sudo mount -a    # 改动 fstab 后先谨慎验证
!
磁盘操作红线

mkfs、fdisk 写入、parted 分区和 dd 可能永久破坏数据。本指南不提供可直接覆盖磁盘的复制粘贴命令；请先在虚拟磁盘上练习并核对设备路径。

网络、DNS 与防火墙

用分层方法判断：接口、路由、端口、DNS 还是应用错误。

网络诊断顺序BASH
ip -br addr
ip route
ping -c 4 1.1.1.1
getent hosts example.org
ss -lntup
curl -I --connect-timeout 5 https://example.org

读懂监听地址

127.0.0.1:8080 仅绑定本机回环地址；0.0.0.0:8080 在所有 IPv4 本地地址监听，但是否可从外部访问仍取决于防火墙、路由和上游策略。

Ubuntu：UFW（启用时）
UFW 检查与规则BASH
sudo ufw status verbose
# 如需开放 HTTP 且确认 UFW 已启用
sudo ufw allow 80/tcp
RHEL：firewalld（启用时）
firewalld 检查与规则BASH
sudo firewall-cmd --state
sudo firewall-cmd --list-all
# 开放 HTTP 并写入持久规则
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --reload
!
远程调整防火墙前先确认 SSH

避免把自己锁在服务器外。先检查现有 SSH 连接、端口、控制台访问方式和规则生效范围，最好保留云控制台或虚拟机控制台作为恢复手段。

SSH 远程管理与文件传输

安全地登录服务器、传文件、减少口令使用。

生成密钥并连接BASH
# 在本地客户端生成专用密钥
ssh-keygen -t ed25519 -C "linux-lab"
# 如果远端允许口令登录，可部署公钥
ssh-copy-id user@server.example.org
ssh user@server.example.org
scp local.txt user@server.example.org:~/

常用 SSH 客户端配置

~/.ssh/config 示例CONFIG
Host lab-server
    HostName 192.0.2.10
    User admin
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 30

192.0.2.10 是用于文档示例的保留地址；连接时需要替换为自己的实验主机 IP 或域名。

修改服务端前先校验BASH
# Debian / Ubuntu 通常服务名为 ssh；RHEL 通常为 sshd
sudo sshd -t
# 校验成功后按系统选择其一
sudo systemctl reload ssh
sudo systemctl reload sshd
!
禁止密码登录的正确时机

先通过新的独立 SSH 会话验证公钥登录和 sudo 权限，再考虑禁用口令登录；更改前保留已有会话及带外恢复路径。私钥切勿复制到服务器公共目录或提交到 Git。

日志系统与故障排查

不靠猜：先拿证据，再定位配置、权限和依赖。

journalctl 排查模板BASH
journalctl -b -p warning --no-pager
journalctl -u nginx --since "1 hour ago" --no-pager
journalctl -u nginx -f
journalctl -k -n 100 --no-pager
systemctl --failed

不同发行版的传统日志位置

类别Ubuntu / Debian 常见RHEL 系常见
认证/var/log/auth.log/var/log/secure
系统消息/var/log/syslog/var/log/messages
systemd 日志journalctljournalctl

日志文件是否存在与 rsyslog 等组件的安装配置有关；无法找到传统文件时，优先查看 journalctl。

故障诊断的五个问题
  1. 什么时候坏的？ 先确定故障窗口。
  2. 哪里坏的？ 网络、服务、数据还是权限。
  3. 谁报告异常？ systemd、内核、Web 服务、数据库。
  4. 最近改过什么？ 配置、部署、更新、证书、规则。
  5. 如何验证恢复？ 用同一测试重新确认结果。
✦
避免只盯着一条报错

错误日志往往是结果，不是根因。结合故障前后的时间、第一条失败记录、依赖服务状态和最近的变更做判断。

Bash、定时任务与备份

把重复操作变成可读、可复用、能失败退出的脚本。

Shell 脚本应做到：可重复运行、输入明确、失败可见、路径安全。一开始只自动化你已经能手工完成的流程。

一个完整的 Bash 例子BASH
#!/usr/bin/env bash
set -euo pipefail

TARGET_DIR="${HOME}/linux-lab/backups"
mkdir -p "$TARGET_DIR"
STAMP="$(date +%Y%m%d-%H%M%S)"

tar -czf "$TARGET_DIR/etc-sample-$STAMP.tar.gz" -C /etc hosts os-release
echo "Backup created: $TARGET_DIR/etc-sample-$STAMP.tar.gz"

Cron 定时任务

编辑和查看个人 crontabBASH

SELinux 是怎么工作的？

Linux 传统 DAC 权限之外，SELinux 提供强制访问控制（MAC）。即使 Unix 文件权限允许操作，SELinux 策略仍可能拒绝它。常见模式为 Enforcing、Permissive 和 Disabled。

SELinux 排查的优先步骤BASH
getenforce
sestatus
ls -Z /var/www/html
# 使用 auditd 且有权限时查看最近 AVC 拒绝
sudo ausearch -m AVC -ts recent
# 常见上下文异常可核对后恢复默认标签
sudo restorecon -Rv /var/www/html
!
不要用「关闭 SELinux」代替解决问题

生产环境应优先分析 AVC 拒绝、文件上下文、布尔开关及策略，而不是为了让程序启动就永久关闭 SELinux。restorecon 只能恢复已定义策略的默认标签，不能代替正确的策略配置。

最小权限原则

让服务使用专门的低权限账户；只开放必要端口；控制 sudo 权限；及时更新软件；为配置和密钥设置合理权限；关键变更要有审计记录。
